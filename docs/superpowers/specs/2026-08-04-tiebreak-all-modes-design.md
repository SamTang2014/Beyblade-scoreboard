# 加賽擴展到循環賽同大循環 — 設計文件

日期：2026-08-04
接續：`2026-08-04-standings-order-design.md`（嗰份改咗排名鏈，令並列少咗但仲會出現；呢份處理「並列咗之後點算」）

## 一句話

加賽由「淨係小組賽有」擴展到三個有排名表嘅模式：單循環任何一段並列都打得，大循環出線線並列就擋住唔准砌籤表，一路打到分勝負為止。

## 點解要做

| 模式 | 而家並列點算 |
|---|---|
| 小組賽 + 淘汰 | 有完整加賽 ✓ |
| 單循環 | 張表出一句「要加賽或者抽籤」，但**個 app 冇得排加賽**。而且冠軍嗰欄已經捧咗第一行做冠軍 —— 而排序最尾 fallback 係個名，即係「邊個係冠軍」變成睇個名點串 |
| 大循環 + 淘汰 | `cutSeeds` 直接 `.slice(0, cutSize)`，**一個 check 都冇**。第 4、5 名並列而頭 4 名入籤表，就靜靜雞按個名攞頭 4 個 |

大循環嗰個係緊要嗰個 —— 佢唔止分唔開，佢係**分錯咗都唔會出聲**。小組賽當初起加賽就係為咗解決同一個問題，但一直冇套用落另外兩個模式。

## 加賽嘅命名空間

加賽場次 id 係 `tb<key>r<次數>m<場次>`。而家第一段係組號；擴展之後：

| 模式 | key 係乜 | 例 |
|---|---|---|
| 小組賽 | 組號 | `tb2r1m1` = B 組第 1 次加賽第 1 場 |
| 單循環、大循環 | **並列嗰班人共用嗰個名次** | `tb3r1m1` = 爭第 3 位嘅第 1 次加賽第 1 場 |

同一場賽事唔會又有組又有名次，所以撞唔到。

`TieState.pool` 改名做 **`key`**，另加 `kind: 'pool' | 'rank'`。唔改名嘅話個 field 會喺單循環度講緊「第 3 名」但個名叫 `pool`，睇 code 嗰個人一定會當佢係組號。

## 三個模式各自點做

| | 邊啲並列要打 | 打完之後 |
|---|---|---|
| 單循環 | **任何一段並列**，包括包尾嗰段 | 排名表**重排、解開並列**；冠軍出返個真名 |
| 大循環 + 淘汰 | 淨係出線線嗰段 | 排名表照顯示並列；擋住唔准砌籤表；種子跟加賽結果 |
| 小組賽 + 淘汰 | 逐組出線線（現狀） | 不變 |

**點解單循環要重排張表，另外兩個唔使。** 小組表係「組內成績嘅記錄」，加賽係另一件事，所以照顯示並列 —— 呢個係上一份 spec 定咗嘅。但單循環張表本身**就係最終結果**，唔重排嘅話你打完加賽返去睇，兩個人仲係並列第 1，等於冇打過。加賽表照樣留喺下面交代邊個點贏。

單循環嗰個「第一位有人並列，要加賽或者抽籤」嘅提示要改：未排加賽就叫人去排，排咗未打完就講「打緊」，打掂咗就唔使再出。

**大循環都要用 `applyRankTiebreaks`，但唔係喺張表度。** 佢張表照顯示並列，`cutSeeds` 入面先套用加賽次序嚟決定邊個入籤表。同一個純 function 兩處用，一處餵去顯示、一處餵去種子。

## 「仲係分唔開」點算

相鄰兩個喺**勝場 → 分差 → 極限次數**三樣都一樣，就當拆唔掂，成班人再打多一輪，**一直打到分勝負為止，唔設上限**。同小組賽現有做法一致。

唔會淨係抽仲並列嗰兩個出嚟打 —— 嗰個要再開一層命名空間，唔抵。

「分得開」嘅定義按有冇出線線分開：

| | 分得開嘅條件 |
|---|---|
| 有出線線（大循環、小組賽） | 線上面嗰個同線下面嗰個唔同就夠。唔關事嗰啲分唔開都唔使再打 |
| 冇出線線（單循環） | **每一對相鄰都要唔同** —— 冇線可劃，所以要排晒先後 |

## 兩個要小心嘅位

**並列一定要由未經加賽嘅排名算起。** 如果由「已經套用咗加賽結果」嗰張表再搵並列，名次會郁，個 key 命名空間跟住飄，已排咗嘅加賽場次認唔返自己。所以永遠由原始 `computeStandings` 搵並列，加賽結果淨係喺顯示嗰層套上去。

**單循環要等成個循環打完先俾排加賽。** 一場都未打嘅時候全部人並列第 1 —— 唔攔住就會即刻彈一句「8 個人要打加賽」出嚟。小組賽而家係靠介面喺 `groupStageComplete` 之後先顯示，新嗰個要喺 engine 度明文擋。

小組賽現有嘅 `tieStates` **唔加呢個 gate** —— 佢打到一半顯示「呢兩個而家並列」係有用嘅資訊，而真正會出事嗰度（砌籤表）本身已經有 `groupStageComplete` 守住。改咗係另一件事，唔喺呢份 spec 範圍。

## 要改嘅嘢

| 檔案 | 改乜 |

### 新 API

```ts
/** 一段並列。 */
export interface TieState {
  /** 命名空間 key：小組賽係組號，其他模式係並列嗰個名次。 */
  key: number
  /** 決定介面點寫個標題。 */
  kind: 'pool' | 'rank'
  ids: string[]
  /** 爭緊幾多個位。null = 冇出線線，要成班排晒先後。 */
  slots: number | null
  attempt: number
  matches: Match[]
  played: boolean
  resolved: boolean
  results: TiebreakRow[]
}

/**
 * 唔分組嘅模式嘅並列。
 *
 * `cut` = 頭幾名有意義（大循環入籤表人數）；null = 冇出線線，
 * 任何一段並列都要拆（單循環）。循環未打完就返吉。
 */
export function rankTieStates(
  players: Player[],
  matches: Match[],
  headToHead: boolean,
  cut: number | null,
): TieState[]

/** 排下一批加賽場次。未打過就排第 1 次；打完但仲分唔開就排下一次。 */
export function nextTiebreakFor(states: TieState[]): Match[]

/** 用加賽結果重排排名表入面並列嗰幾段，順手解開 rank／tied。拆唔掂嘅段原封不動。 */
export function applyRankTiebreaks(rows: StandingRow[], states: TieState[]): StandingRow[]
```

## 測試

**`rankTieStates` —— 單循環（`cut` 係 null）**

- 循環未打完 → 返吉（就算而家全部人並列）
- 打完、一段都冇並列 → 返吉
- 頭兩個並列 → 一個 state，`key` = 1、`kind` = 'rank'、`slots` = null
- 頭兩個並列 + 第 3、4 位又並列 → 兩個 state，`key` 分別係 1 同 3
- 包尾兩個並列 → 都要出 state（「任何一段並列都打」）
- 三個人並列 → 一個 state，`ids` 三個都喺入面

**`rankTieStates` —— 大循環（`cut` 有值）**

- 出線線上下分得開 → 返吉，就算表入面第 6、7 位並列
- 出線線上面並列（第 4、5 位並列，頭 4 名入籤表）→ 一個 state，`slots` = 1
- 並列嗰班全部喺線之上（第 3、4 位並列，頭 4 名入）→ 返吉，唔使拆
- 循環未打完 → 返吉

**加賽結果**

- 單循環：加賽相鄰全部分得開 → `resolved` true
- 單循環：三個人加賽，頭嗰個拆到但後面兩個一樣 → `resolved` **false**（冇線可劃，要排晒先後）
- 大循環：線上線下分得開就夠，唔關事嗰兩個仲並列都當 resolved
- 分唔開 → `nextTiebreakFor` 排下一輪，`round` = attempt + 1
- 一路分唔開就一路排得到（連排三輪唔會炸、id 唔會撞）
- 打緊嗰輪未打完 → 唔會再排多一輪

**`applyRankTiebreaks`**

- 拆掂咗嘅段：按加賽次序重排，`rank` 變返 1／2、`tied` 全 false
- 拆唔掂嘅段：原封不動，仲係並列
- 有兩段並列、一段拆掂一段未 → 拆掂嗰段重排，另一段唔郁
- 重排唔會影響後面嗰啲人嘅名次（頭兩個由並列 1 變 1／2，第 3 位仲係第 3）

**命名空間**

- 單循環爭第 1 位同爭第 3 位嘅加賽，id 唔會撞
- 同一段打第 2 輪，id 同第 1 輪唔會撞
- 加賽場次唔會入到 `computeStandings`（`stage: 'tiebreak'` 本身已經隔咗，加測試釘死）

**`cutSeeds`（大循環）**

- 出線線並列而加賽未打掂 → 返吉（砌唔到籤表）
- 加賽打掂 → 種子跟加賽次序，唔係跟個名

**唔好整爛現有嘢**

- 小組賽全部現有加賽測試照過（`TieState` 換咗 field 名之後）
- 純淘汰模式冇排名表，`standingsTies` 返吉

## 明確唔做

| 項目 | 決定 |
|---|---|
| 加賽輪數上限 | **唔設**。一直打到分勝負為止 |
| 只抽仲並列嗰幾個出嚟重打 | **唔做**。成段重打，唔使開多層命名空間 |
| 抽籤拆並列 | **唔做**（同前三份 spec 一致） |
| 單循環揀「頭幾名要拆」 | **唔做**。任何一段並列都打 |
| 俾人手動跳過加賽 | **唔做** |
| 小組賽 `tieStates` 加「打完先顯示」嘅 gate | **唔做**，唔喺呢份範圍 |
