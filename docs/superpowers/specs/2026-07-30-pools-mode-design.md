# 小組賽 + 淘汰 — 設計文件

日期：2026-07-30
接續：`2026-07-27-knockout-mode-design.md`（嗰份「明確唔做」入面寫住「分組（多個小組）循環」，呢份推翻嗰個決定）

## 一句話

第四個賽制：全部人隨機分幾組，每組組內打單循環，每組頭幾名入淘汰賽爭冠軍。

## 同現有「循環 + 淘汰」有咩分別

| | 循環 + 淘汰（已有） | 小組賽 + 淘汰（呢份） |
|---|---|---|
| 循環階段 | 一個大循環，人人都同其他所有人打 | 分開幾組，淨係同組內嘅人打 |
| 12 個人要打幾多場循環 | 66 場 | 分 3 組 = 18 場 |
| 入籤表 | 總排名頭 N 名 | 每組頭 N 名 |
| 種子 | 跟總排名 | 各組第 1 名排先，跟住各組第 2 名；交叉搵 |

12 個人打 66 場循環，一場 5 分鐘都要五個半鐘。分 3 組得 18 場。**呢個先係開呢個模式嘅原因。**

## 決策紀錄

| 項目 | 決定 | 理由 |
|---|---|---|
| 開賽時揀咩 | **分幾多組**（唔係「每組幾多人」） | 主持人心入面諗嘅係「開幾多個場地／分幾多堆」 |
| 每組出幾多個 | 開賽時揀 1／2／3 | 細場同大場都用得同一個 app |
| 點分組 | **隨機抽籤**，撳「排賽程」嗰下抽，抽完釘死 | 同純淘汰嘅抽籤一致，最少爭議 |
| 組人數唔平均 | 早啲嘅組多一個（13 人分 3 組 = 5／4／4） | |
| 籤表種子 | **交叉搵**：各組第 1 名做上梯次，各組第 2 名做下梯次 | 同組嘅人組內已經打過，唔應該一入淘汰就重演 |
| 遲到加人 | 自動塞落人最少嗰組，補返嗰組嘅新場次 | 同現有「中途加人」一致：打咗嘅一場都唔郁 |
| 手動分組 | **唔做** | |
| 小組出線用抽籤決定並列 | **唔做**（照顯示「並列」） | 同排名表現有做法一致 |
| 各組第 3 名比較後補位（FIFA 玩法） | **唔做** | |
| 季軍戰、雙敗 | **唔做**（同上一份 spec） | |
| 計分 | 同其他模式一樣，Beyblade X，先到 4 分 | |

## 賽制點叫

內部名 `poolsThenKnockout`。介面叫**「小組賽 + 淘汰」**。

順手將現有 `groupThenKnockout` 嘅介面名由「循環 + 淘汰」改做**「大循環 + 淘汰」** ——
兩個名擺埋一齊唔講清楚係分唔到嘅。**淨係改 UI 字，內部名同存檔一律唔郁**
（改內部名要遷移已存嘅賽事，為咗個名唔抵）。

`engine/tournament.ts` 頂要寫低呢個命名陷阱：`stage: 'group'` 係「循環階段」（兩個混合模式都用），
`pool` 先係「小組」。

## 資料模型

### 選手身上加組別

```ts
interface Player {
  id: string
  name: string
  seat: number
  /** 第幾組，1 起計（1 = A 組）。null = 未分組，或者根本唔係小組賽模式。 */
  pool: number | null
}
```

**點解擺喺選手身上而唔係賽事身上擺個 `pools: string[][]`：**
除名一個選手嗰陣，佢自動離組，唔使另外去個陣列度剷返佢。
漏咗剷就會出現一場「對住一個唔存在嘅人」嘅比賽。

### 賽事身上加兩格

```ts
type TournamentMode = 'roundRobin' | 'knockout' | 'groupThenKnockout' | 'poolsThenKnockout'

interface Tournament {
  // …現有欄位…
  /** poolsThenKnockout 專用：分幾多組。其他模式係 null。 */
  poolCount: number | null
  /** poolsThenKnockout 專用：每組出幾多個入籤表。其他模式係 null。 */
  advancePerPool: number | null
}
```

`Match` **唔使改**。場次屬於邊組，睇佢兩個選手就知（同組先會對到），
唔另外存 —— 存低就會有得同選手身上嗰個對唔上。

### 舊存檔照讀得返

`parseTournament` 加：

- 選手冇 `pool` → `null`
- 賽事冇 `poolCount` / `advancePerPool` → `null`
- `pool` 讀到唔係 1 到 `poolCount` 之間嘅整數 → 當 `null`（下次排賽程會當佢係遲到嘅人塞入最細組）
- `mode` 認多一個 `poolsThenKnockout`

匯出檔 `version` **維持 1**：新欄位純粹係加，舊版讀新檔唔會炸。

## 引擎

新檔 `engine/pools.ts`，全部純 function（唔掂 storage、唔掂 React、唔掂 DOM、唔自己搵隨機數）：

```
poolOptions(人數)                      → 揀得幾多組（每組最少 2 人）
poolSizes(人數, 組數)                   → 每組人數，例如 (13, 3) → [5, 4, 4]
advanceOptions(人數, 組數)              → 每組出得幾多個（最多 = 最細嗰組人數）
drawPools(選手[], 組數, rng)            → 抽完組嘅選手[]
assignLatecomers(選手[], 組數)          → 未分組嘅塞落人最少嗰組
poolsOf(選手[])                        → 逐組嘅選手[][]
buildPoolSchedule(現有場次[], 選手[])    → 逐組排／補賽程，再重編同輪次入面嘅次序
poolStandings(選手[], 場次[])           → 逐組嘅排名表
poolSeedOrder(選手[], 場次[], 每組出幾多) → 交叉排完嘅種子順序
```

### 抽組

Fisher–Yates 洗牌（用返 `bracket.ts` 現有嗰個 `drawOrder`），跟住一人一組派落去：
洗完之後第 `i` 個人入第 `(i % 組數) + 1` 組。所以組同組最多爭一個人，
而且早啲嘅組多嗰一個。

rng 由外面傳入，所以測試可以餵固定假 rng。

### 逐組排賽程

每組各自行圓周法 —— 直接用返現有 `generateSchedule` / `mergeSchedule`，
餵入去嘅淨係嗰組嘅人同嗰組嘅場次。**唔重寫排程邏輯**，中途加人嘅處理自動繼承。

輪次對齊：每組自己嘅第 1 輪就係全場第 1 輪。人少嗰組早幾輪打完就冇咗場次。
排完之後同一輪入面按組別 A→B→C 重編 `order`，令 `inPlayOrder` 出嚟嘅次序穩定。

### 「呢輪唞」要改

現有 `byesInRound` 係「呢輪冇得打嘅人」。小組賽度會出事：A 組 4 人 3 輪打完，
B 組 5 人打到第 5 輪，咁 A 組全部人喺第 4、5 輪就會顯示「唞」—— 但佢哋係打完咗。

新規則：**一個人喺第 r 輪算「唞」，條件係佢冇得打，而且佢同組有人喺第 r 輪有場次。**
呢條規則同時覆蓋返其他模式（大家 `pool` 都係 null，即係同一組，行為一模一樣）。

### 逐組排名

同一套 tiebreak，淨係餵入去嘅選手同場次換成嗰組嘅。`computeStandings` 本身唔使改。

### 交叉種子

1. 逐組排名，攞每組頭 `advancePerPool` 個。
2. 分梯次：第 1 梯次 = 各組第 1 名，第 2 梯次 = 各組第 2 名，如此類推。
3. 同梯次之間用**總成績**（全部小組場次一齊計嘅排名）分先後。
4. 種子順序 = 第 1 梯次 ++ 第 2 梯次 ++ …
5. **修補 pass**：用 `seedSlots` 算出首圈點配對，逐對檢查；撞到同組嘅，
   就**郁後面嗰個種子**（位序細嗰個唔郁，保住上梯次嘅位），喺**同梯次**入面搵個對象換。
   換得成嘅條件係兩邊都要合格：換完之後呢一對唔再同組，而且被抽走嗰個原本嗰對亦唔會變成同組
   （對家係輪空就當合格）。逐對按位序掃、逐個候選按種子號由細到大掃，
   第一個合格就換 —— 所以結果係定死嘅，唔靠隨機。搵唔到候選就照擺，唔硬拗。

**點解要修補 pass 而唔係一條死規則：** 試過兩條「聽落好合理」嘅規則都唔work ——

- 梯次照順序排：3 組出 2 個嗰陣，C 組第 1 會首圈撞返 C 組第 2
- 梯次輪轉一格：2 組出 2 個嗰陣，A 組第 1 會首圈撞返 A 組第 2

冇一條固定規則食晒所有組合，所以砌完先檢查再修。

**一個避無可避嘅個案：2 組、每組出 3 個。** 6 個人入 8 人籤表，
兩個輪空位食咗兩個人，剩返 4 個入首圈 —— 邊個組合都一定至少有一場同組內戰。
修補 pass 會做到最少，做唔到零。開賽設定會寫明呢件事，唔扮冇事發生。

### `tournament.ts` 要改嘅嘢

**`startTournament` 改返出嚟嘅嘢。** 而家淨係返 `Match[]`；小組賽模式要順便寫低邊個入邊組，
所以改成：

```ts
function startTournament(t: Tournament, rng: () => number): { players: Player[]; matches: Match[] }
```

其他三個模式照返 `{ players: t.players, matches: … }`。呼叫嘅地方得 `Setup.tsx` 一處。

小組賽模式入面：

- 冇人有 `pool` → `drawPools`（第一次排賽程）
- 已經有人有 `pool` → `assignLatecomers`（撳「補返新場次」）

**`buildCut` 按模式分流**：`groupThenKnockout` 照舊用總排名做種子；
`poolsThenKnockout` 行 `poolSeedOrder`。呼叫嘅地方（`Bracket.tsx`）唔使識分模式。

**`canStart`**、**`MODE_LABEL`**、**`MODE_HINT`**、**`hasStandings`** 加新模式。
`canStart('poolsThenKnockout', …)` 要求：人數 ≥ 4、`poolCount` 喺 `poolOptions` 入面、
`advancePerPool` 喺 `advanceOptions` 入面。

## 順手修一個舊 bug

排名版（`Table.tsx`）而家嘅「冠軍」係 `computeStandings` 排第 1 嗰個。
但 `computeStandings` **唔計淘汰階段**，而 `isTournamentComplete` **計埋**。
所以「大循環 + 淘汰」打完成個籤表之後，排名版會捧咗*循環賽*第一名做冠軍，
唔係*淘汰賽*冠軍。呢個 bug 而家已經存在。

改法：**凡係有籤表嘅模式，冠軍一律睇 `bracketChampion`**，而且要籤表真係打完先 show。
純循環照舊睇排名第 1。`Board.tsx` 嘅 `championLine` 同樣處理。

## 測試

新檔 `engine/pools.test.ts`：

- `poolOptions`：4 人得 2 組；6 人有 2、3 組；12 人有 2 到 6 組
- `poolSizes`：12/3 → [4,4,4]；13/3 → [5,4,4]；總和永遠等於人數
- `drawPools`：組人數啱、每個人啱啱一組、餵同一個假 rng 出同一個結果
- `buildPoolSchedule`：冇跨組對戰、每組場數 = n(n−1)/2、同一輪冇人打兩場
- 遲到加人：入最細組、補返嗰組嘅新場次、已打嘅場次同分數一場都唔郁
- 「呢輪唞」：A 組打完之後，A 組啲人唔會喺後面幾輪顯示「唞」
- `poolStandings`：逐組獨立計，A 組嘅人唔會因為 B 組打完咗而郁位
- `poolSeedOrder`：
  - 2 組出 2 個 → A1 對 B2、B1 對 A2
  - 3 組出 2 個 → 首圈零同組內戰
  - 4 組出 2 個 → 首圈零同組內戰
  - 2／3／4 組出 1 個 → 首圈零同組內戰
  - **2 組出 3 個 → 啱啱一場同組內戰**（寫死做測試，證明我哋知道而且做到最少）
  - 種子梯次冇被修補 pass 搞亂：每個梯次嘅人仍然全部排喺下一梯次之前

`engine/tournament.test.ts` 補：`startTournament` 新回傳格式、`canStart` 新模式、`buildCut` 分流。

`storage.test.ts` 補：冇 `pool` / `poolCount` / `advancePerPool` 嘅舊賽事照讀得返；
`pool` 出界當 null；新模式匯出匯入行得通。
