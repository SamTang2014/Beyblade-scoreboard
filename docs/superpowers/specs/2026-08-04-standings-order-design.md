# 排名次序改制 + 極限勝出次數 — 設計文件

日期：2026-08-04
接續：`2026-07-30-pools-mode-design.md`（嗰份寫住「計分同其他模式一樣」，呢份改嘅係計完分之後**點排名次**）

## 一句話

排名由「勝場 → 對賽成績 → 得分」改成「勝場 → 得分 → 分差 → 極限勝出次數」；對賽成績由第 2 位掉到最尾，而且變成一個可開可閂嘅選項（default 閂）。極限勝出次數要睇得到。

## 點解要改

而家對賽成績排喺第 2 位，即係「你贏過我」大過「你分數高過我」。兩個人 3 勝 1 負，一個 16 分一個 12 分，但係 12 分嗰個嬴過對方，就排佢前面 —— 打得靚嗰個排後。而且呢條規則只喺**啱啱兩個人**同勝場先用得着，三個人並列就自動放棄，變成有時用有時唔用，主持人解釋唔到。

改完之後對賽成績退到最尾，做「乜都拆唔開」嘅最後手段，而且主持人開賽前自己揀用唔用。

## 排名鏈

| | 而家 | 改完 |
|---|---|---|
| 1 | 勝場 | 勝場 |
| 2 | 對賽成績（淨係兩人並列先用） | 總得分 |
| 3 | 總得分 | 得失分差 |
| 4 | 得失分差 | **極限勝出次數** |
| 5 | 仲一樣 → 並列 | 對賽成績 —— **選項開咗先做** |
| 6 | | 仲一樣 → 並列 |

第 5 步閂咗（default）就直接跳去並列。

## 對賽成績點做：小循環

第 5 步唔係「攞兩個人嗰場睇邊個贏」，係**小循環**：淨係攞並列嗰班人**之間**、已經打完嘅小組場次，重新計一次。

```
內部勝場 → 內部分差 → 內部極限次數 → 仲一樣就並列
```

兩個人嘅時候呢條式自動退化成原本嘅對賽成績（贏嗰個內部勝場 1 > 0），所以兩人同三人共用同一條 code path，唔使分開寫。

**三個人回圈嘅例子。** A 贏 B、B 贏 C、C 贏 A，四樣主鏈數字全部一樣：

| | 內勝 | 內差 | 內極限 | 結果 |
|---|---|---|---|---|
| A | 1 | +2 | 2 | 第 1 |
| C | 1 | +2 | 1 | 第 2 |
| B | 1 | −4 | 1 | 第 3 |

內部勝場全部 1（回圈嘅必然結果），要靠內部分差同內部極限先拆到。三樣全同就三個一齊並列，交俾加賽處理。

**細節：**

- 佢哋之間有場未打完 → 嗰場唔計，可能就拆唔到，正常。
- 唔遞迴。小循環拆完仲有人一樣就係並列，唔會再喺並列嗰班人入面開多個小循環。
- 拆得開一部分都算數：3 個人入面 A 拆得出、B 同 C 拆唔開 → A 第 1，B、C 並列第 2。

## 極限勝出次數點數

`round.winnerId === 個人` 而且 `round.finish === 'xtreme'` 就數一次。

**只數計入分數嗰啲 round。** `matchScore` 一到 4 分就唔再數落去（手改過嘅檔可能多咗 round），極限次數要跟同一個界線 —— 否則會出現「總分冇變但極限次數升咗」。

實作上喺 `rules.ts` 抽一個 `scoredRounds(match): RoundResult[]`，`matchScore` 同極限次數兩邊都行佢。兩處各自寫一次條界線就一定會走音。

再喺 `rules.ts` 出一個 `xtremeWins(matches: Match[], playerId: string): number`。排名表、加賽表、入分版三個地方數嘅係唔同批場次，但數法一定要一樣 —— 三邊都叫呢個 function，各自負責餵邊批場次入去。

## 選項

`Tournament` 加 `headToHead: boolean`。

| | |
|---|---|
| default | `false`（閂） |
| 舊檔／舊備份冇呢個 field | `false` —— 即係舊賽事讀返出嚟排名會變，呢個係預期之內 |
| 幾時鎖 | 同賽制一樣，行 Setup 現有嘅 `alreadyStarted`（有任何一場入咗最少一 round）|
| 純淘汰模式 | 唔顯示（冇排名表），值保持 `false` |

**點解開咗波就鎖：** 打到一半改規則排名會大跳；如果已經排咗加賽，改完可能原本並列嘅唔再並列，嗰批加賽場次即刻變咗白打。

介面擺喺 Setup 賽制設定下面，標題「同分點拆」，一句 hint 講明開咗係「四樣都一樣先睇佢哋之間邊個贏過邊個」。

## 極限次數喺邊度睇到

| 位置 | 顯示 | 數邊啲場 |
|---|---|---|
| 入分版，兩邊名下面 | `⚡ 3` | 跟打緊嗰場嘅階段，見下 |
| 入分版 `.rlog` 逐 round 嗰行 | 極限嗰粒標實（⚡ + 高亮） | 當場 |
| 排名表 + 電視版 | 「⚡」欄 | 小組／循環階段全部場次 |
| 加賽結果表 | 「⚡」欄 | 淨係嗰次加賽嘅場次 |

**入分版嗰個數跟打緊嗰場嘅階段**，即係永遠等於「你而家排緊嘅嗰張表」入面嗰個數：

| 打緊嘅場次 | 名下面數乜 | 對得返邊張表 |
|---|---|---|
| `group` | 小組／循環階段全部場次，包括打緊嗰場 | 排名表「⚡」欄 |
| `tiebreak` | 嗰次加賽嘅場次 | 加賽結果表「⚡」欄 |
| `bracket` | **唔顯示** | 淘汰賽冇排名表 |

同一個標籤唔可以喺兩個地方係兩個數 —— 所以唔係「一個賽事總數」，係跟住當前階段走。純淘汰模式一律唔出。

## 加賽排名鏈

`rankByTiebreak` 由「勝場 → 分差」改成「勝場 → 分差 → 極限次數」。同小組表一致，而且加賽場數少，多一條規則拆得開多啲，唔使打第二輪加賽。

`TiebreakRow` 加 `xtreme: number`。

**加賽鏈唔加對賽記錄選項** —— 加賽本身就係拆並列嘅手段，喺拆並列嘅比賽裏面再夾一層拆並列嘅選項係兜返轉頭。

## 測試

排名嘅正確性全部喺 `standings.test.ts`；並列同加賽嘅互動喺 `pools.test.ts` / `tiebreak.test.ts`。

**主鏈**

- 勝場唔同 → 勝場話事，得分再高都冇用
- 勝場同、得分唔同 → 得分話事
- 勝場得分同、分差唔同 → 分差話事（得分一樣但失分唔同）
- 頭三樣同、極限次數唔同 → 極限話事
- 四樣全同、選項閂 → 並列，`tied` 兩個都 true
- 未打完嘅場次唔計入任何一項

**小循環（選項開）**

- 兩個人並列，A 贏過 B → A 排前（退化成對賽成績）
- 兩個人並列，佢哋嗰場未打完 → 仲係並列
- **4 人組，A/B/C 三個 12 分、分差同、極限同**，A贏B、B贏C、C贏A，內部分差分得開 → 拆到 1/2/3，D 第 4
- 同上，內部分差都一樣、內部極限唔同 → 靠內部極限拆
- 同上，內部三樣全同 → 三個一齊並列第 1，`tied` 全 true
- 3 個人入面 A 拆得出、B/C 拆唔開 → A 第 1，B/C 並列第 2
- 小循環淨係計佢哋之間嘅場次 —— 打贏組外人攞嘅分唔會入內部分差
- 選項閂嘅時候，上面幾個 case 全部並列

**極限次數**

- 夠 4 分之後嗰啲 round 唔計入極限次數（同 `matchScore` 同一條界線）
- 輸咗嗰場入面自己贏嗰啲極限 round 照數
- 淘汰賽同加賽場次唔會入到小組表嗰個數
- `xtremeWins` 餵咩場次就數咩場次：同一個選手，餵 group 同餵 tiebreak 出兩個唔同數

**選項同存檔**

- 舊檔（冇 `headToHead`）讀入 → `false`
- `create()` 出嚟嘅新賽事 → `false`
- 匯出再匯入 → 個值保持住
- 賽事開咗波 → 個開關 disabled

**小組模式**

- 逐組獨立算，B 組打完一場唔會郁到 A 組個排名
- 出線線上面並列 → 加賽照觸發（選項閂同開都要測）
- `poolSeedOrder` 嘅交叉種子跟新排名鏈

**加賽**

- 加賽勝場分差同、極限唔同 → 極限拆到，唔使打第二輪
- 加賽三樣全同 → 照排第二輪加賽
