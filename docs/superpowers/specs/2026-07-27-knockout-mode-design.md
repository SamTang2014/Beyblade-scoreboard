# 淘汰制模式 — 設計文件

日期：2026-07-27
接續：`2026-07-27-beyblade-scoreboard-design.md`（嗰份寫住「明確唔做：淘汰賽」，呢份推翻嗰個決定）

## 一句話

開賽時揀三個模式之一：單循環、純淘汰、循環 + 淘汰。

## 決策紀錄

| 項目 | 決定 | 理由 |
|---|---|---|
| 模式 | 三個都要，開賽時揀 | |
| 純淘汰抽籤 | **隨機**，輪空都係隨機抽 | 最公平、最少爭議 |
| 循環 + 淘汰嘅種子 | 用循環賽排名（第 1 對最後、第 2 對第 3） | 打咗成個循環先，用返成績最公道 |
| 入幾多人籤表 | 開賽時揀（頭 2 / 4 / 8…），人數唔夠嘅選項自動禁用 | |
| 改上游場次 | 准，但會**清走下游已入嘅分**，而且事先彈窗講明 | 同「除名」「刪賽事」一致 |
| 季軍戰 | **唔做** | |
| 雙敗淘汰 | **唔做** | |
| 手動拖拉排籤 | **唔做** | |
| 計分 | 同單循環一樣，Beyblade X，先到 4 分 | |

## 資料模型

### 新增

```ts
type TournamentMode = 'roundRobin' | 'knockout' | 'groupThenKnockout'

interface Tournament {
  // …現有欄位…
  mode: TournamentMode
  /** groupThenKnockout 專用：幾多人入籤表。其他模式係 null。 */
  cutSize: number | null
}
```

### `Match` 要改（呢個係核心改動）

而家 `aId` / `bId` 兩個都係必填 `string`，而 `id` 就係對戰雙方排序後嘅 key。
單循環做得到，因為開賽嗰刻已經知道晒邊個打邊個。

**淘汰制唔知。** 決賽開賽時係「四強場1 嘅贏家 打 四強場2 嘅贏家」。所以：

```ts
interface Match {
  id: string
  /** 'group' = 循環階段；'bracket' = 淘汰階段。 */
  stage: 'group' | 'bracket'
  round: number
  order: number
  /** null = 對手未定，等緊上游。 */
  aId: string | null
  bId: string | null
  /** 等緊邊場嘅贏家入呢個位。單循環一律 null。 */
  aFrom: string | null
  bFrom: string | null
  rounds: RoundResult[]
}
```

**場次 id：** 循環階段照舊用對戰雙方（`p1__p2`）；淘汰階段用 `b<輪>m<場>`（例如 `b2m1`）。
兩者唔會撞，因為 pair key 一定含 `__`。

**已存嘅賽事唔會爛：** `parseTournament` 讀到冇 `mode` 就當 `roundRobin`，
冇 `stage` 就當 `group`，冇 `aFrom`/`bFrom` 就當 `null`。

## 籤表點砌

`engine/bracket.ts`，全部純 function：

```
drawOrder(選手[], rng)          → 打亂咗嘅 id 陣列（隨機抽籤）
generateBracket(種子順序[])      → 場次[]（帶住「邊場贏家」指針）
propagate(場次[])               → 上游有結果就自動填落下游
downstreamOf(場次[], 場次id)     → 改呢場會影響到邊幾場
bracketRoundName(場次, 全部場次) → 「決賽」「四強」「八強」…
```

**構造：** 籤表大細 = 大過等於人數嘅最細 2 次方。輪空數目 = 籤表大細 − 人數。
用標準種子位序（size 8 → `[1,8,4,5,2,7,3,6]`），令 1 號同 2 號只會喺決賽相遇。
輪空分俾頭幾個種子；純淘汰模式因為順序本身係隨機抽出嚟，所以等同隨機輪空。

**輪空唔會產生場次。** 首圈某個位淨得一個人，佢直接填落下一輪嗰場，
唔會出現一場「對住空氣」嘅比賽。

## 改錯分點處理

改上游場次時，`downstreamOf` 搵出所有受影響嘅下游場次。如果嗰啲場次已經入咗分，
彈確認：「改咗四強，決賽已經入咗嘅 4–2 會清走，要重新打。確定？」
確認之後：下游場次嘅 `rounds` 清空、`aId`/`bId` 由 `propagate` 重新計。

唔確認就乜都唔郁。

## 介面

**開賽設定**加模式選擇；揀 `groupThenKnockout` 時再揀入幾多人（人數唔夠嘅選項禁用）。

**新增「籤表」畫面**：一欄一輪、由左到右，線連住晉級路線。撳任何一場跳去入分改嗰場。

**Tab 跟模式變：**

| 模式 | Tabs |
|---|---|
| 單循環 | 入分 · 賽程 · 排名 · 矩陣 · 電視 |
| 純淘汰 | 入分 · 籤表 · 電視 |
| 循環 + 淘汰 | 入分 · 賽程 · 排名 · 矩陣 · 籤表 · 電視 |

純淘汰冇排名表同矩陣 —— 淘汰賽分唔到第 3 名（因為唔做季軍戰）。

**入分畫面**喺淘汰階段顯示「決賽」「四強」「八強」，唔顯示「第 N 輪」。

## 測試

`engine/bracket.test.ts`：

- 2、3、4、5、6、7、8、12、16 人都砌到正確籤表
- 輪空數目 = 籤表大細 − 人數；每個人首圈最多出現一次
- 1 號同 2 號種子只會喺決賽相遇
- 贏家自動推進到下一場
- `downstreamOf` 搵得齊所有受影響場次，一場都唔少
- 改上游之後，下游 `rounds` 清得乾淨、參賽者重新計啱

`storage.test.ts` 補：冇 `mode` / `stage` / `aFrom` 嘅舊賽事照讀得返，當單循環。
